Full-tree audit of `codecap` at `482c32e` (helper + plasmoid + CI + packaging).
This file is the **findings register**: what is wrong, where, and what it costs.
The **order of work** is [`plan-hardening.md`](./plan-hardening.md).

Domain language is [`CONTEXT.md`](../CONTEXT.md); architecture is [`design.md`](./design.md).
Nothing here proposes a product change — every finding is a gap between what the
ADRs already decided and what the code does.

## C — Critical

### C-1 · Today / This week / This month are computed in UTC for every non-UTC user
`plasmoid/contents/ui/main.qml:60-67` → `internal/usage/usage.go:55-58`

The plasmoid derives the timezone by regexing the parenthesised suffix of
`new Date().toString()`. That yields a **display name**, not an IANA ID:

```qml
const fallback = now.toString().match(/\(([^)]+)\)$/)   // "Central European Summer Time"
```

`time.LoadLocation` rejects it, and the helper swallows the error:

```go
loc, err := time.LoadLocation(strings.TrimSpace(timezone))
if err != nil {
    loc = time.UTC        // silent
}
```

**Verified:**

```
time.LoadLocation("Central European Summer Time") -> unknown time zone
time.LoadLocation("CEST")                         -> unknown time zone
time.LoadLocation("Coordinated Universal Time")   -> unknown time zone
time.LoadLocation("Europe/Copenhagen")            -> ok
```

Day, week and month boundaries therefore fall on UTC midnight for essentially
every user. In `Europe/Copenhagen` (UTC+2 in summer) everything consumed between
00:00 and 02:00 local is booked to the previous day, and the same shift moves
week and month edges. `CONTEXT.md` promises "in the desktop's local timezone".
Session is unaffected — it is a rolling 5 h window and never touches `loc`.

The user cannot detect this: the numbers look plausible and there is no staleness
or fallback indicator.

**Fix.** Qt's JS engine has no `Intl`, so QML cannot cheaply produce an IANA ID.
The clean fix runs the other way: send `""` from the plasmoid and have `computeAt` use
`time.Local` when the timezone argument is empty — the helper runs in the same session
and already honours `TZ` / `/etc/localtime`. Either way an *unresolvable* timezone must
surface as an error, not a silent UTC substitution. Record the empty-string convention in
ADR 0011's bus contract.

### C-2 · `GetSnapshot` does blocking network and a full disk walk inline
`internal/dbusapi/server.go:35-46`

ADR 0011 says *"the helper owns polling and file watch"* and ADR 0006 says
*"fetch Allowance about once a minute"*. The implementation does the opposite:
every `GetSnapshot` synchronously classifies the face, re-parses every usage log,
performs an OAuth refresh if needed, and performs the vendor fetch — then replies.

Measured cost of the log walk alone: **2.54 s and 825 MB allocated per call** on a
311 MB Account Home (see Evidence). On top of that sit two uncancellable HTTPS
round-trips. The widget blocks for the whole duration; the D-Bus reply can exceed
the 25 s default method timeout, which surfaces as the error callback in
`main.qml:101-105` → `unknown_allowance`.

**Fix.** Serve a cached snapshot immediately; refresh in a background loop and
push `Changed`. This is what ADR 0011 already specifies.

### C-3 · No HTTP timeouts anywhere, and the credentials lock is held across the network call
`internal/allowance/service.go:38`, `internal/creds/creds.go:128`, `internal/allowance/client.go:32`

All three paths use `http.DefaultClient` — no `Timeout`, no `DialContext` deadline,
no `ResponseHeaderTimeout`. There is no `context.Context` in the codebase, so
nothing is cancellable.

`EnsureAccessToken` takes the credentials lock (`creds.go:74`) and holds it via
`defer unlock()` across the refresh at `creds.go:91`. A hung TCP connection — a
blackholed SYN, a captive portal, a laptop resumed from suspend — parks that
goroutine **forever** while holding the lock. Every later `GetSnapshot` then fails
after the 5 s busy deadline (`creds.go:282`), and the minute poller blocks on the
same lock. The helper is wedged for the rest of the session, and per H-6 nothing
restarts it.

**Fix.** `&http.Client{Timeout: 15 * time.Second}` as a floor; properly, thread a
`context.WithTimeout` from `GetSnapshot` through `Resolve` / `EnsureAccessToken` /
`FetchUsage` using `http.NewRequestWithContext`. Do the network call outside the lock.

### C-4 · `accountHome` is unvalidated caller input used as a filesystem base
`internal/dbusapi/server.go:35` (declared `:70`), reaching `internal/creds/creds.go:180-241`

`accountHome` is a plain `s` argument. It is never validated, never canonicalised,
and is used directly for reads, writes, `os.CreateTemp`, `os.Rename`, recursive
walks and recursive inotify watches. The helper performs no peer check
(`GetConnectionUnixUser`/`GetConnectionCredentials`), and the shipped
`contrib/dbus/dev.codecap.Helper.service` carries no bus policy. The design docs
assume the plasmoid is the only caller; nothing enforces it.

The sharpest consequence is a **confused deputy on the credentials file**.
`saveOAuthTokens` reads `<accountHome>/.credentials.json` with `os.ReadFile`
(which follows symlinks), then writes a temp file *in `accountHome`* and renames
over the path — and `rename(2)` replaces the **symlink itself**, not its target:

1. A session-bus peer creates `/tmp/evil/` and symlinks
   `/tmp/evil/.credentials.json` → `~/.claude/.credentials.json`.
2. It calls `GetSnapshot("/tmp/evil", …)`. `face.Classify` follows the link, sees a
   real `accessToken`, returns `unknown_allowance`, so `addAllowance` runs.
3. `EnsureAccessToken` loads the *real* tokens. Once they are within the 30 s
   refresh skew (`creds.go:84`) — the peer polls, or simply waits for normal expiry —
   it refreshes and writes the **fresh access + refresh token** to
   `/tmp/evil/.credentials.json` as a new regular file.
4. The user's real file keeps the now-rotated refresh token.

That is credential theft plus denial of the user's own login. Same-uid peers could
read `~/.claude` directly, so the sharp case is a peer with the session bus but not
the filesystem: a Flatpak or snap with `--socket=session-bus`.

The same unvalidated path is a **file-creation primitive** — the helper will create
`.credentials.json.lock` and `.credentials.*.tmp` in any directory the caller names
(`creds.go:273`, `:216`).

**Fix.** Resolve `accountHome` against an allowlist, or take it from the helper's own
config rather than the bus argument. Independently: open the credentials file with
`O_NOFOLLOW`, `fstat` it (`st_uid == getuid()`, `!S_ISLNK`, `st_nlink == 1`), and
`Lstat` the destination before `Rename`.

## H — High

### H-1 · A FIFO named `*.jsonl` hangs a D-Bus call permanently
`internal/usage/usage.go:106-128`

`listJSONLFiles` collects every non-directory entry ending in `.jsonl`. `WalkDir`
uses `Lstat`, so FIFOs, device nodes and symlinks are all included. `consumeFile`
then calls plain `os.Open`, and opening a FIFO for reading **blocks until a writer
appears**. Verified: `mkfifo p/x.jsonl`; the walk lists it, `os.Open` hangs
indefinitely.

Because godbus dispatches each call in its own goroutine, repeated calls leak
goroutines and fds without bound. Consumed Usage never renders again.

**Fix.** Filter on `d.Type().IsRegular()` in the walk, and open with
`O_RDONLY|O_NOFOLLOW|O_NONBLOCK` plus an `fstat` `S_ISREG` check.

### H-2 · Watcher → signal → full rescan is an undebounced feedback loop
`internal/usagewatch/watch.go:121-123` → `internal/dbusapi/server.go:161-167` → `main.qml:89`

`m.onChange` fires on **every individual** fsnotify event — no debounce, no
coalescing. Each one broadcasts `Changed`, which makes the plasmoid call
`GetSnapshot`, which re-parses the entire log corpus (C-2, 2.54 s / 825 MB).
An active Claude Code session appends to JSONL many times per second.

**Fix.** Coalesce events over ~1 s before emitting; cache the computed usage with a
short TTL; track per-file offset + mtime and parse only appended bytes.

### H-3 · Unbounded watchers, inotify instances and goroutines from caller-controlled paths
`internal/dbusapi/server.go:39` → `internal/usagewatch/watch.go:34-79`

`ensureWatch` runs on **every** `GetSnapshot`, ungated by face (unlike
`addConsumedUsage:97` and `addAllowance:116`). The only guard is a non-empty string
and that `<accountHome>/projects` is a directory. Each distinct path allocates a new
`fsnotify.Watcher` (one `inotify_init` fd), a permanent goroutine, and a map entry
keyed on the caller's string; `addRecursive` then adds one watch per subdirectory.

`fs.inotify.max_user_instances` defaults to 128 and is a **per-user** resource, so
exhausting it breaks file watching for the whole desktop session — indexers,
editors, sync clients — not just codecap. Nothing ever removes a watcher:
entries are deleted only in `Manager.Close`, which nobody calls.

**Fix.** Cap watched homes with a small LRU and evict; only watch a home that
passed classification; call `Manager.Close` on shutdown.

### H-4 · Unbounded poller registry with serial, untimed network calls
`internal/allowance/poller.go:36-46`, `:69-81`; registered at `internal/dbusapi/server.go:136-138`

`p.accounts` only grows. `hasUsableOAuth` (`face.go:41-57`) requires nothing more
than a non-empty `accessToken` string, so any number of fake homes can be
registered and polled forever, every 60 s, for the life of the session. Rebinding
the widget to a different Account Home leaks the old one the same way.

`tick` calls `resolve` **serially** with no timeout, so N registered accounts mean N
sequential lock acquisitions plus refresh and fetch attempts per tick. Once that
exceeds 60 s, ticks are dropped and the effective poll rate collapses.

**Fix.** Bound the registry, drop accounts whose credentials file has vanished, run
resolves with per-account timeouts, wire up `Stop`.

### H-5 · The `Server` has no synchronisation, and the concurrent code has 0% coverage
`internal/dbusapi/server.go` (all methods); `internal/allowance/poller.go:24-82`

godbus dispatches every method call in its own goroutine (`conn.go:435`). `design.md`
explicitly supports the same applet on the panel, the desktop and the tray, so
concurrent `GetSnapshot` for one Account Home is the normal case, not an edge case.
Those calls race with the poller goroutine on the same `Service`, the same
`LastKnownStore` and the same credentials file.

`go test -race ./...` passes only because `NewPoller`, `Ensure`, `Stop`, `loop`,
`tick`, `pollAccountHome` and `emitChanged` are **all 0%** — the racy code is never
instantiated in a test. That is a false green, not an absence of races.

**Fix.** Add `-race` to CI, add `poller_test.go`, add a test that calls `GetSnapshot`
concurrently with `pollAccountHome`, and add an admission limit on concurrent work.

### H-6 · The systemd restart guarantee from ADR 0015 does not exist
`contrib/dbus/dev.codecap.Helper.service`, `contrib/systemd/codecap.service`, `cmd/codecap/main.go:20-26`

Verified contents:

```ini
# contrib/dbus/dev.codecap.Helper.service      # contrib/systemd/codecap.service
[D-BUS Service]                                [Unit]
Name=dev.codecap.Helper                        Description=codecap session helper
Exec=/usr/bin/codecap                          [Service]
                                               Type=dbus
# no SystemdService=                           BusName=dev.codecap.Helper
                                               ExecStart=/usr/bin/codecap
                                               Restart=on-failure
                                               RestartSec=2
                                               # no [Install]
```

Without `SystemdService=`, dbus-daemon forks the binary directly and systemd is
never involved — `Restart=on-failure`, journal unit attribution, and any future
hardening are all inert. Without `[Install]`, `systemctl --user enable` cannot work
either. ADR 0015 and `design.md:38` both claim "systemd --user restarts it on crash".
It does not.

Worse, a user who works around this by starting the unit manually while a
D-Bus-activated instance is running hits `log.Fatalf("service name already in use")`
(`main.go:25`) → exit 1 → restart every 2 s for the rest of the session.

**Fix.** Add `SystemdService=codecap.service` and `[Install] WantedBy=default.target`;
exit 0 rather than 1 when the name is already owned. Assert both in `verify-install.sh`.

### H-7 · CI is green but blind
`.github/workflows/ci.yml:36-43`

The workflow runs `go vet`, `make test`, `make test-install`. Missing: `gofmt`,
`-race`, any linter, coverage, `shellcheck`, `qmllint`, `reuse lint`, `govulncheck`,
`timeout-minutes`, `concurrency`. Consequences measured today:

- `gofmt -l .` fails on `internal/dbusapi/server_test.go` — **already unformatted on main**, which is direct proof the gate is missing.
- `golangci-lint run ./...` reports 5 issues (4 unchecked `Close()`, 1 staticcheck QF1012).
- `Export` (`server.go:48-94`) is **0%** — it builds the entire introspection XML by hand. A wrong arg signature (`"i"` vs `"s"`, wrong order) is invisible to every test and only fails at runtime against `main.qml:88-94`. The D-Bus contract is completely unverified on both sides.
- `RefreshAccessToken` (`creds.go:102-124`) is **0%** — and it rewrites `~/.claude/.credentials.json`. Highest blast radius in the repo, zero tests.
- `Compute`/`ComputeWithRates` are **0%**: tests call the internal `computeAt` directly, so the production call chain from `server.go:101` is never exercised end to end.

### H-8 · `PKGBUILD` cannot build a valid Plasma 6 package
`PKGBUILD:11-13, 18-19, 21-29`

`depends=('plasma-framework')` is the **KF5/Plasma 5** package; Plasma 6 ships
`libplasma`. The widget imports `org.kde.plasma.workspace.dbus` (from
`plasma-workspace`) and `org.kde.kirigami`, neither declared; the helper needs
`dbus`. `source=()` and `sha256sums=()` are empty and the build does `cd "$startdir"`,
so it only builds from a local checkout — it cannot go to the AUR and nothing is
integrity-checked. There is no `check()`, so `makepkg` never runs the tests.
`pkgver=0.2.0` is duplicated in `plasmoid/metadata.json` with nothing asserting they match.

### H-9 · `sudo make install` rebuilds as root inside the user's checkout
`scripts/install.sh:13,16` with `Makefile:21` (`install: build`)

`install.sh` runs `make build` as the user, then `sudo make install`. Because
`install` depends on `build`, root re-runs `go build`, leaving `bin/` owned by root
in the working tree — the next `make build` or `make clean` fails with EPERM. It also
runs the Go toolchain and module downloads as root.

### H-10 · Test files ship into the installed plasmoid
`Makefile:29` (`cp -a plasmoid/. $(DESTDIR)$(PLASMOIDDIR)/`)

Verified after `make install DESTDIR=…`:

```
…/plasma/plasmoids/dev.codecap.plasmoid/test/load-logic.mjs
…/plasma/plasmoids/dev.codecap.plasmoid/test/logic.test.mjs
```

`verify-install.sh:16-24` only checks that four files exist and never asserts the
absence of anything, so the layout gate passes.

### H-11 · `PREFIX` is a lie: the install prefix is hardcoded in the service files
`contrib/dbus/…:3`, `contrib/systemd/…:7`, `scripts/verify-install.sh:16-19,26`, `Makefile:4`

Verified:

```
$ make install DESTDIR=/tmp/p2 PREFIX=/usr/local && scripts/verify-install.sh /tmp/p2
missing: /tmp/p2/usr/bin/codecap
```

The binary lands in `/usr/local/bin`, both service files still point at
`/usr/bin/codecap`, and the verifier looks in `/usr` unconditionally. Anyone
installing to `/usr/local` — the common source-install prefix — gets a helper that
can never be activated, and the widget sits on `unknown_allowance` forever with no
error surfaced.

## M — Medium

### M-1 · The credentials lock has no stale-lock recovery; one SIGKILL disables refresh permanently
`internal/creds/creds.go:269-287`

`O_CREATE|O_EXCL` on `<accountHome>/.credentials.json.lock`, retried for 5 s. The PID
is written at `:275` and **never read**. No mtime staleness check, no `flock`, no
startup cleanup. If the helper is killed between `:273` and the deferred
`os.Remove` — OOM, logout race, power loss — the lock file persists across reboots
and every refresh then fails with `credentials lock busy`, which maps to a permanent
`unknown_allowance` with nothing telling the user a stray dotfile is the cause.

Sub-points, checked individually:

- **Symlink attack: not exploitable.** `O_EXCL` fails on an existing symlink. This part is correct.
- **PID reuse:** no impact today, but it becomes live the moment someone adds "break the lock if the PID is dead".
- **Unlock is unconditional** `os.Remove` with no proof this goroutine still owns the lock.
- **The lock is taken before anything is read** (`:74`, `:103`), so a read-only Account Home fails the whole allowance path even where a pure read would do.
- **Cross-process:** Claude Code itself does not honour this lock, so the read-modify-write in `saveOAuthTokens` can still clobber a concurrent CLI write.

**Fix.** `syscall.Flock` on the credentials file — the kernel releases it on process
death, which removes stale-lock and PID-reuse concerns entirely.

### M-2 · Any 403 forces a refresh-token burn, once per minute
`internal/allowance/client.go:63-65`, `internal/allowance/service.go:59-68`

`FetchUsage` maps **both** 401 and 403 to `errUnauthorized`, and `Resolve` answers
with `RefreshAccessToken` — the unconditional variant that refreshes regardless of
expiry. A 403 from rate limiting or WAF blocking therefore triggers a forced OAuth
refresh every poll tick, indefinitely. Against a provider that rotates refresh
tokens that is sustained rotation churn and a good way to get the grant invalidated.
There is no backoff and `Retry-After` is ignored.

**Fix.** Force-refresh only on 401; treat 403 and 429 as transient with exponential
backoff and a per-hour refresh cap.

### M-3 · Last-known cache: fixed temp filename, no exclusive create
`internal/allowance/lastknown.go:65-72`

```go
tmp := path + ".tmp"
if err := os.WriteFile(tmp, data, 0o600); err != nil {
```

`O_WRONLY|O_CREATE|O_TRUNC`, no `O_EXCL`, no randomness. Concurrent saves for one
account interleave on the same temp path and can land torn JSON, which then fails
`json.Unmarshal` at `:87` and returns a hard error from `fallback` — turning the
offline-resilience feature into an extra failure mode.

### M-4 · The cache is unauthenticated and a future timestamp makes it immortal
`internal/allowance/lastknown.go:86-98`

`account_home` is written into the JSON but never verified on load. And
`now.Sub(fetchedAt) > LastKnownTTL` is one-sided: a `fetched_at` in the future gives
a negative duration, so the entry never expires and is served as `FaceReady` forever.

### M-5 · `/tmp/codecap-cache` fallback is a predictable path in a world-writable directory
`internal/allowance/lastknown.go:42-51`

If `XDG_CACHE_HOME` is unset **and** `os.UserHomeDir()` fails — reachable for a
D-Bus-activated service depending on the activation environment — the root becomes
`/tmp/codecap-cache`, with filenames `sha256(accountHome)[:16]`, fully predictable.
`MkdirAll` succeeds on an existing directory without checking its owner or mode, so a
different uid can pre-create it and plant `<sha>.json.tmp` as a symlink to a file the
victim owns; `os.WriteFile` follows symlinks. Note also that any session-bus peer can
call `org.freedesktop.DBus.UpdateActivationEnvironment` and influence
`XDG_CACHE_HOME` for future activations.

### M-6 · No D-Bus input validation and no concurrency limit
`internal/dbusapi/server.go:35-46`

Names, path and interface are internally consistent with `design.md:5-10`, and only
`GetSnapshot` is exported — that part is correct. Missing: `accountHome` is not
required to be absolute or `Clean`, with no length cap (D-Bus allows strings up to
the 128 MB message limit, and such a string becomes a permanent map key in both
`Manager.watchers` and `Poller.accounts`); `timezone` reaches `time.LoadLocation` on
every call doing uncached filesystem I/O (path traversal itself **is** blocked by Go's
own `containsDotDot` check — verified); and there is no admission control on the
unbounded goroutine-per-call dispatch.

`weekStart int32` is fully handled by `normalizeWeekStart` — no issue there.

### M-7 · The snapshot has no schema version and no way to say "degraded"
`internal/snapshot/snapshot.go:33-42`, `internal/dbusapi/server.go:103,122`

Helper and plasmoid are separately installed and independently versioned (that is the
whole point of the two-artifact split in `design.md`), but the JSON carries no
`schema_version`. A field rename is a silent breakage.

Separately, every error is logged and dropped: `addConsumedUsage` and `addAllowance`
call `log.Printf` and return. The UI cannot distinguish "you used nothing today" from
"reading the logs failed", so it renders zeros as fact. Same for the silent UTC
fallback in C-1.

### M-8 · No shared contract fixture between helper and plasmoid
`internal/snapshot/snapshot_test.go` vs `plasmoid/test/logic.test.mjs`

Both sides test their own idea of the snapshot shape. `docs/design.md:40-47` documents
a third. Nothing pins them together, and `Export`'s introspection XML (0% covered) is a
fourth statement of the same contract. One golden JSON fixture consumed by the Go test,
the JS test and an introspection assertion would make drift impossible.

### M-9 · File-watching error branches and the nested-directory path are barely tested
`internal/usagewatch/watch.go` — `Ensure` 57%, `loop` 56%, `addRecursive` 67%, `errorsJoin` 0%

One test writes one file into one pre-existing directory. Untested: the
**nested-directory auto-watch** at `watch.go:113-119` — which is *the* refresh
mechanism when Claude Code starts a new project — the double-check-locking window at
`:69-74`, the `watcher.Errors` branch, and `Close()`. If `addRecursive` fails on a new
directory it only logs (`:116`) and usage silently stops updating for that project.

Note also `addRecursive` returns the walk error, so one unreadable subdirectory aborts
the entire watch setup.

### M-10 · No QML linting — 374 lines of `main.qml` are unverified
`.github/workflows/ci.yml`, `plasmoid/contents/ui/main.qml`

The JS tests are genuinely good: all 14 `logic.js` functions are exported for test and
10 tests cover 11 of them, and `load-logic.mjs:13` uses `new Function(source)` so a
*syntax* error in `logic.js` does fail CI. But `logic.js` is 182 of ~692 QML/JS lines.
`main.qml` — the D-Bus `asyncCall` (`:88-107`), the `Changed` watcher (`:181-197`),
three `Timer`s, the ECB XHR (`:130-155`) — has no automated checking of any kind.

### M-11 · REUSE compliance is claimed but not enforced, and 6 files fail today
`REUSE.toml:1-13`

Covered by neither a header nor `REUSE.toml`: `go.sum`, `plasmoid/metadata.json`,
`plasmoid/contents/config/main.xml`, `contrib/dbus/dev.codecap.Helper.service`,
`contrib/systemd/codecap.service`, and — a genuine miss, since every sibling `.qml`
has one — `plasmoid/contents/ui/logic.js`.

### M-12 · Dependencies are stale and nothing scans them
`go.mod:5-10`

`golang.org/x/sys v0.13.0` is roughly two years behind `v0.47.0`; `godbus/dbus/v5` is
`v5.1.0` against `v5.2.2`. No Dependabot or Renovate config, no `govulncheck`. Both
libraries sit directly in the path of untrusted input — D-Bus messages and inotify
events. (`govulncheck` could not run here: the egress proxy blocks `vuln.go.dev`.)

### M-13 · No uninstall path
`Makefile:16`, `scripts/install.sh:18-25`

No `make uninstall`, no `scripts/uninstall.sh`. A user who installed with `sudo` has no
supported way to remove the binary, the two service files, the plasmoid tree, or
`~/.cache/codecap`. Separately, `install.sh:23` falls back to
`rm -rf "$LOCAL_PLASMOID"` with no confirmation — the path is fixed and well-formed so
it is not a `rm -rf /` hazard, but it silently destroys local plasmoid edits.

### M-14 · Global mutable test seams block parallel tests
`internal/face/face.go:18-21`

`stat` and `readFile` are package-level `var`s swapped by tests. That is global mutable
state: no test in `face` can use `t.Parallel()`, and a future parallel run corrupts
neighbours. Same class of problem as `dbusapi.Export` (`server.go:48`) constructing all
its dependencies internally, which is why `Export` is untestable and 0% covered.

### M-15 · The rate table silently prices unknown models as Sonnet
`internal/usage/rates.go:35-52`

# Plasmoid (QML / JS)

Separately numbered (`P-…`) because the plasmoid is a separately installed artifact.
Plasma 6 API claims below were checked against upstream sources: libplasma `applet.h`,
plasma-workspace `components/dbus/*`, plasma-desktop `desktoppackage/contents/applet/*`,
Kirigami `platform/platformtheme.h`, and the QML `StandardPaths` type.

**Read this section first.** Four of these are critical, and together they mean the
widget does not actually work as shipped: it cannot be opened by mouse, it never
receives the push signal, it rejects the documented `~/.claude` path, and it mislabels
currency for every non-USD user.

## P-C1 · Typing `~/.claude` can never work — `homeDir` is a `file://` URL
`plasmoid/contents/ui/main.qml:16-19`, `plasmoid/contents/ui/logic.js:11-13`

```qml
readonly property string homeDir: StandardPaths.writableLocation(StandardPaths.HomeLocation)
```

The QML `StandardPaths` type — unlike C++ `QStandardPaths` — returns a **`url`**.
Assigned to a `string` property it stringifies to `file:///home/you`, so
`Logic.expandPath("~/.claude", homeDir)` yields `file:///home/you/.claude`. That string
goes over the bus to `GetSnapshot` (`main.qml:88`), and `face.Classify`
(`internal/face/face.go:29-31`) does `os.Stat` on it, fails, and returns `signed_out`.

`README.md:92` explicitly tells the user to "Browse… **or type `~/.claude`**", and
`design.md:87` specifies the `~/.claude` placeholder hint. Everyone who follows that
instruction gets a permanent, unexplained "Signed out" face. Only the Browse… button
works, because `configGeneral.qml:53` calls `selectedFolder.toLocalFile()`.

**Fix.** Strip the scheme at the boundary and make `expandPath` reject a `file://`
prefix. Add the regression test `expandPath("~/.claude", "file:///home/me")`.

## P-C2 · The `Changed` signal is never delivered — the handler name is wrong
`plasmoid/contents/ui/main.qml:181-198`

```qml
DBus.SignalWatcher {
    function onReceivedSignal(message) { ... }     // never called
```

`org.kde.plasma.workspace.dbus`'s `SignalWatcher` emits no `receivedSignal`. Its
`Q_SIGNALS` block has only `enabledChanged` / `busTypeChanged` / `serviceChanged` /
`pathChanged` / `interfaceChanged`. `dbussignalwatcher.cpp` dispatches by dynamically
looking up a JS function named `"dbus" + message.member()` on the watcher and calling it
with the **already-decoded** signal arguments. Its own qmltypes documentation states it:
"The function name of the signal handler needs to be prefixed with `dbus`."

So `message.member` and `message.arguments` (`main.qml:190,193`) are never evaluated, and
the entire push path of ADR 0011 is dead code. Consumed Usage updates only on the 30 s
poll, which defeats the "watch logs" clock of ADR 0006 — and makes H-2's rescan storm the
*only* thing the helper's watcher accomplishes.

**Fix.**

```qml
function dbusChanged(accountHome) {
    if (accountHome === root.resolvedAccountHome()) root.updateSnapshot()
}
```

## P-C3 · The popup cannot be opened with the mouse
`plasmoid/contents/ui/main.qml:252-260`, `plasmoid/contents/ui/CompactRing.qml`

**Verified:** `grep -rn "MouseArea|TapHandler|expanded" plasmoid/contents/ui/` returns
**nothing**.

Click-to-expand lives in plasma-desktop's `DefaultCompactRepresentation.qml`, which holds
the `MouseArea` that does `plasmoidItem.expanded = !wasExpanded` plus
`Plasmoid.secondaryActivated()` on middle click. Supplying your own
`compactRepresentation` replaces it. The wrapper that remains, `CompactApplet.qml`, only
provides the `ToolTipArea` and keyboard Space/Enter → `Plasmoid.activated()`.

The entire expanded face specified in `design.md:83-85` — bars, Usage Credit, the Consumed
Usage FormLayout, the placeholders — is therefore unreachable by mouse. The widget looks
inert.

**Fix.** Wrap the ring in a `MouseArea` (`acceptedButtons: Qt.LeftButton | Qt.MiddleButton`)
that toggles `root.expanded`, mirroring the default representation.

## P-C4 · The FX regex cannot parse the real ECB feed, and the failure reports success
`plasmoid/contents/ui/logic.js:147`, `main.qml:139-147`

```js
var re = /currency='([A-Z]{3})'\s+rate='([0-9.]+)'/g
```

Single-quoted attributes are legal XML but vanishingly rare; the published
`eurofxref-daily.xml` uses double quotes. The regex then matches nothing,
`parseEcbRates` returns `{EUR: 1.0}`, `usdToDisplayRate` hits `if (!rates.USD) return 1.0`
(`logic.js:159-161`), and the caller treats `rate > 0` as success:

```js
if (rate > 0) { fxRate = rate; fxUsingUsdFallback = false; ... }
```

Every non-USD user therefore sees **raw USD amounts labelled with their own currency**
— "74.50 DKK" that is really $74.50 — cached in config for 24 h, with no "rate
unavailable" note. That directly violates `design.md:44` and ADR 0014, which require
falling back to USD *visibly*.

The unit test cannot catch it: `logic.test.mjs:80-81` writes its fixture with single
quotes, so the test validates the assumption against itself.

**Fix.** Accept both quote styles — `/currency=["']([A-Z]{3})["']\s+rate=["']([0-9.]+)["']/g`
— or parse with `XmlListModel`. Rewrite the test fixture as a verbatim excerpt of the live
feed. (Live verification was not possible from this sandbox: the egress proxy returns 403
for `ecb.europa.eu`. Accepting both quote styles is correct either way; confirm the live
format when implementing.)

## P-H1 · `Connections { target: Plasmoid; onConfigurationChanged }` binds a signal that does not exist
`plasmoid/contents/ui/main.qml:207-212`

`Plasma::Applet` has no `configurationChanged` signal — `applet.h` declares
`configNeedsSaving()`, `userConfiguringChanged(bool)`, `configurationRequiredChanged(…)`,
`hasConfigurationInterfaceChanged(…)`, and `configuration` is
`Q_PROPERTY(… READ configuration CONSTANT FINAL)`. QML logs "Detected function
onConfigurationChanged in Connections element" and never calls it.

Changing Account Home or Display Currency therefore triggers no refresh. Going
unbound → bound is papered over by the 30 s poll; switching *between* two Account Homes
shows the old account's data for up to 30 s.

**Fix.** Bind declaratively instead:

```qml
readonly property string accountHome: Plasmoid.configuration.accountHome
onAccountHomeChanged: updateSnapshot()
readonly property string cfgCurrency: Plasmoid.configuration.displayCurrency
onCfgCurrencyChanged: refreshFxRate()
```

## P-H2 · Timezone
See **C-1**. The plasmoid side is `main.qml:60-67`; `weekStart()` at `:56-58` is by
contrast **correct** — QML `Locale.DayOfWeek` is Sunday=0…Saturday=6, which
`normalizeWeekStart` maps properly.

## P-H3 · Mutating `snapshot` after assignment notifies nothing — failure faces render blank
`plasmoid/contents/ui/main.qml:81-86`, `:104-108`

```js
snapshot = Logic.emptySnapshot()      // fires snapshotChanged with face === "unbound"
snapshot.face = "unknown_allowance"   // notifies nothing
snapshot.account_home = resolvedAccountHome()
```

Every binding on `root.snapshot.*` keeps observing `face === "unbound"`.

In the reject path (`:104-108` — helper present, call failed) the damage is total:
`toolTipMainText` falls through to `i18n("codecap")` (`:231-233`); the Unknown Allowance
placeholder requires `face === "unknown_allowance"` (`:338`) so it stays hidden; the
Consumed Usage FormLayout requires ready/unknown_allowance (`:346`) so it hides too. The
user gets a **completely blank popup**, in exactly the case `design.md:20` says must show
Unknown Allowance.

**Fix.** Build the object, then assign once.

## P-H4 · The FX cache is not keyed by currency
`plasmoid/contents/ui/main.qml:123-129`, `plasmoid/contents/config/main.xml:13-21`

`main.xml` stores `fxRateUsdToDisplay`, `fxFetchedAt` and `fxUsingUsdFallback` — but not
*which currency the rate is for*, and the cache check is purely age-based. Switch Display
Currency from DKK to GBP and every List Price is multiplied by the DKK rate and labelled
"GBP" until 24 h elapse. Nothing calls `refreshFxRate()` on a config change either (P-H1),
so the next tick just re-reads the stale cache.

**Fix.** Add `fxCurrency` to `main.xml` and invalidate when it differs.

## P-H5 · `usdToDisplayRate` returns `1.0` for "no rate", which the caller cannot distinguish
`plasmoid/contents/ui/logic.js:155-169`, `main.qml:139-147`

Three paths return `1.0`: missing `rates.USD`, missing target currency, and the legitimate
`targetCurrency === "USD"`. Since the config field accepts any string
(`configGeneral.qml:41-47`), an unsupported ISO code silently renders USD numbers under
the wrong code — same symptom as P-C4, independent cause.

**Fix.** Return `0` for "no rate available" and let `main.qml:139` fall into the
`fxUsingUsdFallback` branch, which already sets the correct note.

## P-H6 · The FX failure path never records `fxFetchedAt` → ECB is polled every 60 s forever
`plasmoid/contents/ui/main.qml:48-54`, `:149-153`

The failure branch writes `fxRateUsdToDisplay` and `fxUsingUsdFallback` but not
`fxFetchedAt`, so the cache test at `:124` stays false and every 60 s tick issues another
`XMLHttpRequest` to `ecb.europa.eu`: **~1440 requests per day per widget instance** while
offline — or, per P-C4, permanently for every non-USD user. `design.md:44` specifies a
*daily* rate.

**Fix.** Record the timestamp on failure too (or a shorter `fxRetryAt` backoff) and raise
the timer to an hour; a 24 h cache does not need a 60 s poll.

## P-H7 · The applet config is written to disk every 60 s
`plasmoid/contents/ui/main.qml:117-119`

The USD branch — the `en_US` default — writes `fxFetchedAt = nowUnix` on every tick, and
`nowUnix` genuinely changes, so the config group is dirtied and saved every minute for the
life of the session. Once P-H1 is fixed this would also re-trigger `updateSnapshot()` per
minute, adding a D-Bus round-trip.

**Fix.** Write only on actual change.

## P-H8 · `asyncCall` omits `signature`, forcing an `Introspect` round-trip per poll
`plasmoid/contents/ui/main.qml:89-94`

`dbuspendingreply.cpp`: when a message has arguments but no `signature`, it first issues
`org.freedesktop.DBus.Introspectable.Introspect`, parses the `direction="in"` args out of
the XML, and only then encodes. If the signature still comes back empty it calls with
**unencoded** arguments — a JS number could marshal as something other than `i`, and
`GetSnapshot` (declared `ssi`, `internal/dbusapi/server.go:68-74`) would reject it. Today
every 30 s poll in every widget instance costs two round-trips plus an XML parse.

**Fix.** Add `"signature": "ssi"`. (This is also the practical argument for H-7's
introspection test: the XML in `Export` is load-bearing at runtime, not documentation.)

## Plasmoid test coverage

`plasmoid/test/logic.test.mjs` covers 11 of the 14 exported `logic.js` functions in 10
tests, and `load-logic.mjs:13` uses `new Function(source)`, so a *syntax* error in
`logic.js` does fail CI. That is a real safety net and worth keeping.

What it does not reach — note how closely this tracks the bug list above:

- **`parseEcbRates` against the real feed.** The fixture at `logic.test.mjs:78-82` uses single quotes, so it validates the P-C4 assumption against itself.
- **`usdToDisplayRate` fallbacks** — missing `USD`, missing target, empty map. Would have caught P-H5.
- **`normalizeSnapshot` with partial input.** The test at `:24-39` asserts the *buggy* P-M5 behaviour as correct.
- **`formatMoney` / `formatTokens` are effectively untested**: the test replaces `Number.prototype.toLocaleString` with a Node stub whose `format`/`precision` defaults differ from QML's — which is exactly why P-M7 is invisible.
- `parseSnapshot` with a non-string argument (the D-Bus unwrapping at `main.qml:96-102` can hand it an object or `undefined`); `localeCurrencyCode` prefix fallbacks and the unknown-locale default; `compactIcon("unbound", …)` and its `default:` branch; `formatTimeToReset` with negative and sub-60 s deltas; `allowanceFillColor` at exactly 80 and 100 and stale-vs-exhausted precedence.

**Nothing verifies any `.qml` file at all.** There is no QML test harness and CI installs
no Qt, so none of P-C2, P-C3, P-H1, P-H3, P-M2, P-M12 — every one of which is a
*non-existent name* or a *missing element* — can be caught by anything in the repo today.
That is the single largest coverage gap in the project, and it is why four critical
plasmoid bugs shipped to `main` with a green pipeline.

Ordered by cost, what closes it:

1. **`qmllint`** over `plasmoid/contents/**/*.qml` with the Plasma/Kirigami import paths available. Cheapest by far; catches P-L6 and, with typeinfo present, non-existent `Connections` handlers (P-H1, P-M2).
2. **`kpackagetool6 --type=Plasma/Applet --show`** on `metadata.json` in `verify-install.sh`, which today only greps for the `Id`. Catches P-M13 and P-L7.
3. **`qmltestrunner6` under `QT_QPA_PLATFORM=offscreen`** for the pure components. `CompactRing` and `AllowanceBar` take only plain properties, so their colour, visibility and geometry behaviour (P-M1, P-M2, P-L5) is testable with Kirigami installed and no D-Bus.
4. **`dbus-run-session` plus a stub `dev.codecap.Helper`** — the real Go helper pointed at a temp Account Home, or a ~30-line python-dbus fake — driving `main.qml` in `qmltestrunner6`. This is what exercises P-C2, P-C3, P-H3, P-M3, P-M4 and P-M6: the failure and partial-data faces that today have zero coverage in either language.
5. **The shared snapshot fixture of M-8**, consumed by the Go tests, the JS tests and an introspection assertion, so QML-side normalization is tested against real helper output instead of hand-written literals.

# Addendum — found while testing on a real desktop, 2026-08-22

The audit was written without a Plasma session. Four things it got wrong or
missed surfaced within an hour of someone actually installing the branch. They
are recorded here because the pattern matters more than the individual bugs:
every one of them is a QML type or API detail that reading could not settle and
running could.

## A-1 · The plasmoid never started the helper it was waiting for
`plasmoid/contents/ui/main.qml` (pre-existing; the audit missed it)

`updateSnapshot` refused to call the helper unless
`DBusServiceWatcher.registered` was true. That property means "the service is
registered on D-Bus right now" — its own documentation says exactly that — not
"the service can be activated". The helper is D-Bus activated, so the first
call is what starts it. Nothing ever called it, so nothing ever started it, and
the widget sat on "Helper unavailable" indefinitely.

`design.md:38` had said the opposite from the beginning: *"The first widget
call starts it"*, and *"If the package is not installed, the call fails →
Unknown Allowance"*. The implementation inverted it, and both the audit and its
QML pass read `helperAvailable` as reasonable.

Masked for the author because `README.md` suggests a `busctl` check that
activates the helper by hand; ADR 0015 then keeps it up for the session.

## A-2 · A QML url is not a string, twice more
`plasmoid/contents/ui/logic.js`, `plasmoid/contents/ui/configGeneral.qml`

`P-C1`'s fix used `(value || "").trim()`. A url is truthy, so it survived the
`|| ""`, and it has no `trim()`. The binding threw. The Node test passed a
string fixture and could not see it.

The folder picker used `selectedFolder.toLocalFile()`. QML url values have no
`toLocalFile` — `typeof u.toLocalFile` is `"undefined"`, verified by running
it. The handler threw and choosing a folder silently did nothing.

Both are the same mistake as the original `P-C1`: reasoning about a QML url as
though it were a `QUrl` in C++ or a string in JavaScript.

## A-3 · A hand-written D-Bus signature broke every call
`plasmoid/contents/ui/main.qml` (introduced by this branch, finding `P-H8`)

`P-H8` recommended adding `"signature": "ssi"` to skip an Introspect
round-trip. Wrong format. `dbusconnection.cpp:90` builds the signature it
derives from introspection as `'(' + types + ')'`, and the documented example
passes `"(u)"` for a single uint32 — the parenthesised struct form.
`dbusencoder.cpp` takes one signature per `encode()` and reads the first
complete type from it, so a bare `"ssi"` encodes the argument list wrongly and
the call fails.

The audit proposed this change as an optimisation without checking the format,
which is the same class of error as the bugs it was cataloguing.

## A-4 · The configuration page is not a page
`plasmoid/contents/ui/configGeneral.qml`

`AppletConfiguration.qml:126-146` shows what the loader does:

```js
const props = { "title": item.name };
config.keys().forEach(key => { props["cfg_" + key] = config[key]; });
pushReplace(Qt.resolvedUrl(item.source), props);
```

The page is pushed onto a Kirigami page stack and is given `title` plus a
`cfg_<key>` for **every** key in `main.xml`. The current root is a
`Kirigami.FormLayout`, which is not a Page and has no `title`, so the journal
carries "Created graphical object was not placed in the graphics scene" and a
failed `title` assignment on every open. The four FX cache keys the page does
not edit produce their own warnings.

The page works — text can be typed, the folder picker returns — so this is
noise rather than breakage, and it is deliberately left alone until there is a
way to test a config page rather than guess at its root type. Fixing it means
a Page-derived root, which is `P-M16`'s territory.


## A-5 · One Account Home, two Accounts

Verified against a real machine, and the correction of a wrong conclusion drawn
earlier in this same session.

The Allowance figures and the Consumed Usage figures the widget shows side by
side belonged to **different Accounts**:

| Shown | Account | Read from |
|---|---|---|
| Session 0 %, Weekly 67 % | work | `<accountHome>/.credentials.json` |
| Consumed Usage, 63 M tokens today | private | `<accountHome>/projects/**` |

Both were correct in isolation. Session really was 0 % — that Account had not
been used that day — and the token totals really were incurred. They simply do
not describe the same Account, and the widget presents them as though they do.

**The earlier conclusion recorded here, that the OAuth endpoint disagreed with
Claude Code, was wrong.** The two never described the same Account: the endpoint
answered for the credentials in the Account Home, Claude Code's panel for the
login its running session held. Nothing in the vendor data was inconsistent, and
`internal/allowance/map.go` was correct throughout. That was the third time in
one session that a conclusion was drawn from data that could not support it.

### Why the premise does not hold

`CONTEXT.md` defines the term as a one-to-one relationship:

> **Account Home**: The local directory that belongs to **one Account** on this
> machine. It holds **that Account's** credentials and logs.

> **Account**: […] Allowance comes from that Account; **Consumed Usage comes
> from the local logs that belong to it.**

Claude Code uses `~/.claude` for whichever Account is logged in. Switching
Accounts replaces `.credentials.json` but leaves `projects/` untouched, so the
transcripts accumulate across every Account that has ever run there. The
directory is therefore one Account's credentials next to many Accounts' logs, and
ADR 0004's "bind Account Home" gives one Account only by accident — whenever the
user has never switched.

This is not a defect in any function. Every layer does what it was asked to do.
The domain model asked for something the filesystem does not provide.

### The logs cannot be split, but the directories can

Two facts settle it.

**The transcripts carry no Account identifier.** Counting the top-level keys
across 5000 lines of a real `projects/` tree gives `type`, `sessionId`,
`timestamp`, `uuid`, `parentUuid`, `userType`, `entrypoint`, `cwd`, `version`,
`gitBranch`, `message`, `requestId` and a long tail of tool and hook fields.
Nothing names an Account, a user or an organisation. `sessionId` identifies a
session, `userType` and `entrypoint` are categories. So filtering the logs of one
directory by Account is not possible, and option 1 above is out.

**Claude Code can put each Account in its own directory.** From the Claude Code
documentation:

> If you set `CLAUDE_CONFIG_DIR`, every `~/.claude` path on this page lives
> under that directory instead.

The paths on that page include `projects/<project>/<session>.jsonl` and the
credentials, so the variable relocates both together. One config directory per
Account is therefore one Account's credentials beside that Account's logs —
exactly what `CONTEXT.md` defines an Account Home to be, and exactly what ADR
0004 binds a widget instance to.

So the domain model is right and needs no revision. What is missing is that
nothing tells the user the model depends on this. `README.md` names `~/.claude`
as the example Account Home without saying that a second Account needs a second
directory, and a user who switches Accounts in place gets one Account's Allowance
beside another Account's Consumed Usage, with nothing in the widget to indicate
it.

**Recommended:** document the setup — a second Account means
`CLAUDE_CONFIG_DIR=~/.claude-work claude`, and a widget instance bound to that
directory. Add it to `README.md` next to the Account Home instructions, and to
ADR 0004 as the condition its premise rests on.

Two limits worth stating with it. A directory that has already served more than
one Account keeps the mixed history: the split applies to sessions from then on.
And the widget cannot detect the mixed case, because there is nothing in the logs
to detect it with — which is an argument for documenting it prominently rather
than relying on a warning that cannot be built.


## A-6 · Claude Code keeps its own token and cost aggregate

`~/.claude/stats-cache.json` holds what `/usage` shows. Its shape on a real
machine:

```
.version, .lastComputedDate
.dailyActivity[11]      date, messageCount, sessionCount, toolCallCount
.dailyModelTokens[11]   date, then per-model token counts
.modelUsage.<model>     inputTokens, outputTokens, cacheReadInputTokens,
                        cacheCreationInputTokens, webSearchRequests,
                        costUSD, contextWindow, maxOutputTokens
```

**It cannot replace the log walk.** The Session window is a rolling five hours
and these are daily buckets, so the widget's headline figure is not derivable
from it; and the daily array held 11 entries where "this month" needs up to 31.
Whether that is a property of the file or of that machine's history is not
established. `modelUsage` is lifetime totals with no time bound, and the file
sits in the config directory, so it shares the Account mixing of A-5.

**It is worth having as a cross-check.** Nothing has ever verified that
codecap's Consumed Usage agrees with what Claude Code shows the same user.
Comparing a day's tokens against `dailyModelTokens` for that date, and
`costUSD` against the List Price `internal/usage` estimates, would settle it.

That bears directly on `M-15`. `internal/usage/rates.go` carries three cards
matched by substring — opus, sonnet, haiku — and prices anything unmatched as
Sonnet without saying so. The models on this machine were `claude-opus-5`,
`claude-sonnet-5`, `claude-sonnet-4-6` and `claude-haiku-4-5-20251001`: the
substrings still match, but no card names a current model, and the rates were
written for an earlier generation. `costUSD` gives a reference to check them
against rather than trusting a hardcoded table.

Suggested as a test rather than a feature: a comparison run against a real
`stats-cache.json`, reported as a percentage difference, so a drifting rate
table becomes visible instead of silently mispricing every figure the widget
shows. The format is undocumented and may change, which is an argument for
using it in a check that can fail loudly, not in the code path that produces
the numbers.

## What this changes about the rest of the plan

Phase 5.2 was scheduled after everything else on the grounds that a QML test
harness is expensive. It cost about twenty minutes — `qmltestrunner` with
`QT_QPA_PLATFORM=offscreen` and six `qml6-module-*` packages — and it found
`A-2` immediately, in a fix that had already been committed and reported as
done. It should have come first.

Phase 5.3, the D-Bus stub under `dbus-run-session`, is what would have caught
`A-1` and `A-3`. It is now the highest-value remaining item in the plan, not
the last one.

## What is already right, and should not regress

Worth stating explicitly, because a findings list reads worse than the code is:

- **No credential ever reaches a log line, an error string, or the snapshot.** The `Snapshot` struct has no credential field, and every `log.Printf` call site was traced. The two-artifact split in `design.md` — plasmoid never touches tokens — holds in the implementation.
- **TLS verification is intact.** No custom `Transport`, no `InsecureSkipVerify` anywhere. Both response reads are capped at 1 MB, and since Go's transport decompresses transparently the cap applies to decompressed bytes, so gzip bombs are bounded.
- **No SSRF vector.** `APIBaseURL` and `TokenBaseURL` are struct fields defaulted to constants with no env var, config file or D-Bus path that sets them — the test seam is not reachable in the shipped binary.
- **No reachable panic was found.** Every pointer deref in `map.go:53-91` is nil-guarded, `weekStartAt` is bounded to 7 iterations, `normalizeWeekStart` has a `default`, and the int64 token sums cannot practically overflow.
- **Credentials file permissions are handled correctly** (L-2), and the lock's `O_EXCL` genuinely defeats the symlink attack (M-1).
- `go vet` is wired and clean; `make test` really does run both the Go and the JS suites; `make test-install` is a real install-layout smoke test that runs in CI; `permissions: contents: read` is correctly minimal; `-trimpath` is set for build reproducibility.
- On the plasmoid side: `logic.js` is genuinely separated from the QML for testability, all 14
  functions are exported for test, and `load-logic.mjs` fails CI on a syntax error. `weekStart()`
  is correct. The USD-fallback branch correctly refuses to guess a rate. `KPackageStructure` and
  `X-Plasma-API-Minimum-Version` in `metadata.json` are right, and the plasmoid never touches a
  credential — the ADR 0007 / 0008 split is real in the code.
- The domain vocabulary in `CONTEXT.md` is carried consistently into type names, JSON keys and face constants. That is rare and it is why this audit could be written against the ADRs rather than against guesswork.
